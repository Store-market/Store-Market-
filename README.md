# Store Market 🇩🇿

سوق إلكتروني جزائري متعدد البائعين، مستقل عن AMG Brain، موجّه للعملاء والبائعين والمالك عبر الولايات الـ58.

## ما هو موجود في فرع التطوير
- واجهة React + TypeScript + Vite متجاوبة، بالعربية والفرنسية، مع RTL/LTR.
- تصفح المنتجات والبحث والتصنيفات والسلة.
- عميل API موحد يربط الواجهة بـ Cloudflare Pages Functions.
- تسجيل العملاء وطلبات انضمام البائعين، تسجيل الدخول والخروج، وجلسات خادمية.
- فضاء البائع لإرسال المنتجات للمراجعة وعرض طلباته.
- Checkout تجريبي COD فقط، مع إعادة احتساب الإجمالي والتحقق من المخزون على الخادم.
- لوحة المالك لإحصاءات المتجر ومراجعة البائعين والمنتجات والطلبات وتغيير الحالات.
- قاعدة بيانات D1 ومخطط SQL وفهارس ومحفزات تمنع بيع مخزون غير متاح.
- GitHub Actions لفحص بناء Vite عند التحديثات.

## التشغيل المحلي للواجهة
1. Node.js 20 أو أحدث.
2. `npm install`
3. `npm run dev`
4. لفحص الإنتاج: `npm run build` ثم `npm run preview`.

تشغيل الواجهة وحده لا يشغّل قاعدة البيانات؛ تحتاج API إلى ربط D1 على Cloudflare Pages.

## نشر Cloudflare Pages
- المستودع: `Store-market/Store-Market-`.
- فرع التطوير: `store-market-fresh`.
- Framework preset: Vite.
- Build command: `npm run build`.
- Build output directory: `dist`.
- Pages Functions موجودة في `functions/`، وملف `public/_redirects` يوجّه مسارات SPA.

## إعداد قاعدة البيانات والحساب الإداري
1. أنشئ Cloudflare D1 database باسم `store-market-db`.
2. نفّذ محتوى `migrations/0001_initial.sql` مرة واحدة على قاعدة D1.
3. من إعدادات Cloudflare Pages → Settings → Bindings، اربط قاعدة D1 باسم binding `DB`. لا تضع معرّف قاعدة البيانات في المستودع؛ احتفظ به داخل إعدادات Cloudflare.
4. أضف Pages secrets: `OWNER_EMAIL` بقيمة البريد الإداري الذي تملكه، و`OWNER_SETUP_KEY` بمفتاح عشوائي قوي. لا تضع الأسرار في GitHub أو المحادثات.
5. بعد نشر Functions، أرسل طلب POST واحداً إلى `/api/setup-owner` مع الترويسة `x-owner-setup-key` وجسم JSON من الشكل `{"name":"اسم المالك","password":"كلمة مرور قوية لا تقل عن 12 حرفاً"}`. لا ترسل كلمة المرور إلى أي شخص.
6. احذف `OWNER_SETUP_KEY` من إعدادات Pages بعد نجاح إنشاء المالك.
7. اختبر `/api/health` ثم التسجيل والدخول وإضافة منتج ومراجعته وإنشاء طلب تجريبي.

## حدود النسخة الحالية
- لم يتم حتى الآن إنشاء D1 وربطها بحساب Cloudflare أو نشر Functions والتحقق من التشغيل الفعلي؛ لذلك لا تعتبر الحسابات والطلبات متاحة على موقع حي حتى إكمال الإعداد أعلاه.
- المنتجات الثمانية القديمة بيانات عرض فقط. الطلبات الحقيقية لا تقبل إلا المنتجات المنشورة فعلياً في D1.
- الدفع COD تجريبي فقط؛ لا يوجد تحصيل مالي.
- CIB والبطاقة الذهبية/Edahabia والمحافظ لا تُفعّل إلا عبر مزود رسمي واتفاق حساب تجاري واختبارات.
- شركات التوصيل، التسعير حسب الولاية، تتبع الشحنات، الإرجاع والنزاعات تحتاج تكاملات واتفاقيات فعلية.
- Facebook/Instagram/Meta غير مربوطين. أي ربط مستقبلي يجب أن يستخدم OAuth وواجهات Meta الرسمية وموافقة المالك؛ لا scraping.
- لا يوجد حالياً نظام مراجعات موثّق، مفضلة خادمية، كوبونات، محاسبة/عمولات بائعين، رسائل داخلية أو مركز دعم متكامل.
- لا تنشر AI أو تغيّر أسعار/مخزون أو ترسل رسائل وإعلانات تلقائياً دون موافقة المالك.
- لا تضع كلمات مرور أو مفاتيح API أو رموز جلسات في المستودع.

## الخصوصية والأمان
كلمات المرور مشتقة باستخدام PBKDF2-SHA256، والجلسات محفوظة كـ hash داخل D1 وتُرسل عبر Cookie من نوع HttpOnly/Secure/SameSite. الأدوار مفروضة على الخادم. يلزم إجراء مراجعة أمنية واختبارات تحميل واستعادة قبل الاستخدام التجاري.
