# Store Market 🇩🇿

واجهة متجر إلكتروني جزائري متعددة البائعين — نسخة أولية تجريبية.

## الحالة الحالية
- واجهة React + TypeScript + Vite.
- العربية والفرنسية مع دعم اتجاه RTL/LTR.
- تصفح تجريبي للمنتجات والتصنيفات والبحث.
- سلة تجريبية محفوظة محلياً في المتصفح (localStorage).
- صفحات تعريفية لفضاء البائع ولوحة الإدارة.
- لا توجد حتى الآن قاعدة بيانات أو مصادقة أو طلبات حقيقية أو تكامل دفع/توصيل.

## التشغيل المحلي
1. ثبّت Node.js 20 أو أحدث.
2. نفّذ `npm install`.
3. نفّذ `npm run dev`.
4. لفحص نسخة الإنتاج نفّذ `npm run build` ثم `npm run preview`.

## النشر على Cloudflare Pages
- اربط مستودع GitHub `Store-market/Store-Market-` بحساب Cloudflare Pages.
- اختر الفرع `store-market-fresh` حتى تتم مراجعة التغييرات قبل دمجها إلى `main`.
- Build command: `npm run build`.
- Build output directory: `dist`.
- Framework preset: `Vite`.
- لا يحتاج هذا الإصدار إلى متغيرات بيئة أو مفاتيح API.
- ملف `public/_redirects` يضمن توجيه مسارات تطبيق الصفحة الواحدة إلى `index.html`.

## قبل إطلاق متجر حقيقي
يجب إضافة backend وقاعدة بيانات دائمة، ومصادقة آمنة وصلاحيات خادمية للمالك والبائع والعميل، وتدفقات طلبات ومخزون حقيقية، ثم اختبارها. لا تفعّل الدفع الإلكتروني أو التوصيل أو ربط Meta قبل إعداد تكامل رسمي واختباره. لا تضع الأسرار أو كلمات المرور في المستودع.

## بيانات العرض
كل المنتجات والأسعار والمتاجر الحالية بيانات توضيحية وليست عروضاً تجارية حقيقية.


## API backend (Cloudflare Pages Functions + D1)

تمت إضافة API أولية تشمل:
- تسجيل عميل، وطلب انضمام بائع بحالة pending.
- تسجيل دخول وجلسات خادمية داخل D1، مع كلمات مرور مشتقة عبر PBKDF2.
- عرض المنتجات المنشورة، وإرسال منتجات البائع للمراجعة.
- إنشاء طلب تجريبي بالدفع عند الاستلام فقط، مع التحقق من المخزون.
- واجهات إدارية لمراجعة البائعين والمنتجات وإحصاءات المتجر.
- حماية المسارات حسب دور الحساب.

### إعداد مطلوب قبل التشغيل
1. أنشئ قاعدة D1 باسم `store-market-db` من لوحة Cloudflare.
2. نفّذ SQL الموجود في `migrations/0001_initial.sql` على قاعدة D1.
3. استبدل `REPLACE_WITH_CLOUDFLARE_D1_DATABASE_ID` في `wrangler.toml` بمعرّف قاعدة البيانات الفعلي.
4. أضف متغيرات Pages Functions السرية `OWNER_EMAIL` و`OWNER_SETUP_KEY` من إعدادات Cloudflare. لا تضع القيم السرية في GitHub أو المحادثة.
5. بعد نشر Pages Functions، نفّذ طلب إعداد المالك مرة واحدة إلى `/api/setup-owner` مع ترويسة `x-owner-setup-key` وجسم JSON يحوي `name` و`password` (كلمة مرور قوية لا تقل عن 12 حرفاً). احذف السر `OWNER_SETUP_KEY` بعد الإنشاء.
6. اختبر `/api/health` ثم التسجيل والدخول وواجهات البائع والمالك.

**تنبيه:** الـ API مضافة في المستودع لكنها ليست مرتبطة بعد بواجهة المتجر، ولم تُنشر أو تُختبر على قاعدة D1 فعلية. يجب عدم اعتبارها جاهزة للإنتاج قبل الربط والاختبار الأمني. الدفع الحقيقي والتوصيل وMeta ما زالت غير مفعلة.
